# 数学魔法岛 — AI学习伙伴 + 亲子共学 完整方案

## 上下文

**背景**：现有的儿童教育产品都是"工具型"——出题、批改、推送内容。孩子跟工具没有情感连接，用完即走。但最有效的学习是关系驱动的。

**核心洞察**：
- 6岁女孩，数学一般，需要补幼小衔接
- 喜欢魔法/宠物/公主风
- 父亲是程序员，可以每天15-20分钟陪学
- 家里有电视大屏+投屏条件

**要解决的问题**：做一个6岁女孩每天期待打开的数学学习产品，让她追着爸爸说"我想跟嘟嘟玩"——而数学自然地融入其中。

**与竞品的本质区别**：别人做"AI数学题工具"，我们做"一个有数学任务的魔法世界"。

## 一、产品概念

### 产品名称：数学魔法岛 (Math Magic Island)

### 一句话描述
一个生活在数学魔法岛上的AI宠物伙伴，需要孩子和家长的帮助来解开数学谜题、恢复岛屿魔法。每天15分钟，亲子轮流协作闯关。

### 核心循环
```
打开应用 → 嘟嘟迎接（记得昨天进度）→ 探索今日新区域 → 
家长导航/发现谜题 → 孩子解数学题 → 嘟嘟反馈/庆祝 → 
解锁新内容 → 嘟嘟说明天见 →
第二天嘟嘟会问"还记得昨天我们学了什么吗？"
```

## 二、AI伙伴角色设计：「嘟嘟」

### 2.1 角色设定

| 属性 | 设定 |
|------|------|
| 外形 | 像仓鼠+兔子混合的小圆球，毛茸茸，粉色/奶油色。大眼睛，小短腿 |
| 性格 | 好奇、有点胆小但勇敢、容易开心、偶尔迷糊需要帮忙 |
| 语言风格 | 童言童语，句子短，爱用拟声词（"哇！""哎呀！""嘿嘿~"） |
| 住在 | 数学魔法岛一棵大树下的蘑菇屋里 |
| 最喜欢的 | 数学水晶（答对获得）、星星饼干、小朋友来找它玩 |
| 最害怕的 | 数学乌云（做错的题会变成乌云遮住水晶） |

### 2.2 AI记忆系统（这是壁垒）

嘟嘟拥有三层记忆，随着使用变深：

**L1 — 基础记忆（第1天就有）**
- 孩子的名字和年龄
- 喜欢的颜色/风格
- 当前进度在哪个区域

**L2 — 学习记忆（积累中）**
- 上次在哪里卡住了
- 哪种题型做得快/慢
- 最容易犯什么错
- 孩子最擅长的领域

**L3 — 情感记忆（长期建立）**
- 昨天嘟嘟跟孩子说了什么笑话
- 上一次两人一起打败了什么"乌云boss"
- 孩子教了嘟嘟什么（错题纠正后嘟嘟会说"谢谢你教会我！"）
- 特殊时刻（连续做对、很大进步、生日）

### 2.3 记忆驱动的个性化示例

```
第1天：
嘟嘟："嗨！我叫嘟嘟！你叫什么名字呀？"
孩子："我叫乐乐"
嘟嘟："乐乐！好好听的名字！嘿嘿，我带你去看看我的蘑菇屋吧~"

第3天（乐乐上次在凑十法卡住了）：
嘟嘟："乐乐你来啦！我一直在等你~ 上次那个7+5的魔法，我今天又练了练，好像懂一点了！你再教教我好不好？"

第10天（记录显示乐乐口算速度提升了）：
嘟嘟："乐乐你好厉害呀！现在你算得比我快啦！你看，这朵小花就是因为你进步才开的！"
```

## 三、亲子轮流协作机制

### 3.1 角色分工

| 环节 | 谁主导 | 操作方式 | 干什么 |
|------|--------|----------|--------|
| 探索 | 家长 | 手柄方向键 | 在岛上移动，发现谜题、宝藏、隐藏区域 |
| 挑战 | 孩子 | 口头回答/手柄A键确认 | 解数学题，家长可以读题、给提示 |
| Boss战 | 轮流 | 轮流答题 | 综合关卡，家长做难的，孩子做适合她水平的 |
| 装饰 | 孩子 | 手柄选择 | 给嘟嘟的蘑菇屋买家具、换装扮（用积分） |
| 回顾 | 一起 | 屏幕查看 | 看今天的收获、嘟嘟的成长、明天的预告 |

### 3.2 每日15分钟节奏

```
0-2分钟   嘟嘟迎接 + 回顾昨天（AI对话，情感连接）
2-5分钟   家长探索今日区域（操控移动，发现3-5个谜题）
5-12分钟  孩子挑战数学题（每道题后嘟嘟给即时反馈）
12-14分钟 亲子Boss合作题（一道综合题，轮流完成）
14-15分钟 结算奖励 + 嘟嘟说明天见 + 岛屿变化展示
```

### 3.3 轮流设计的要点

- **家长不考核孩子**。家长的角色是"帮嘟嘟忙"，不是"看孩子做题对不对"
- **挫败安全**。题做错了，乌云罩住的是嘟嘟的水晶，不是孩子的分数。孩子帮嘟嘟驱散乌云，产生保护欲
- **孩子有掌控感**。装饰蘑菇屋、选择路线、喂养嘟嘟——这些是孩子独享的权力
- **家长有退路**。家长不会做浅奥题不影响——可以选择"跟嘟嘟一起想想"模式，嘟嘟会给提示

### 5.3 AI对话系统设计

嘟嘟的对话不是自由对话——自由对话会导致角色人格漂移和内容失控。采用**模板+AI参数化**的混合方案：

```
┌─────────────────────────────────────────┐
│           对话触发条件                    │
│  (进入岛屿/答对/答错/连续答对/卡住...)    │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│          模板选择器                       │
│  根据场景+记忆上下文选择对话模板           │
│  如：on_correct_answer_first_try        │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│          AI参数化填充                     │
│  模板+孩子名字+题目+进度+昨日记忆          │
│  → LLM生成具象化、带情感的对话            │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│          安全过滤器                       │
│  检查：无负面评价、无比较、无成人话题      │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│          输出 → TTS语音 + 气泡文字        │
└─────────────────────────────────────────┘
```

**为什么不直接用LLM自由对话？**
- 儿童产品需要角色人格一致性，自由对话会漂移
- 延迟问题：TTS合成需要时间，模板+参数化可以在答对瞬间就开始播放语音
- 安全可控：模板范围内不会产生不适当的输出
- 成本可控：模板化后仅需LLM做小量参数填充

### 5.4 前端场景渲染方案

魔法岛使用**2D俯视/侧视混合视角**：

- **探索模式**：俯视2D地图，家长用手柄移动角色（像素级简单画风）
- **挑战模式**：切换到大字体、大画面的题目界面（电视优化）
- **对话模式**：嘟嘟特写+对话框气泡+动画表情

岛屿素材全部由AI生成一次后本地缓存，包括：
- 地形瓦片（草地、森林、山洞、神殿）
- 嘟嘟的多套表情和动作
- UI元素（水晶计数器、进度条、按钮）
- 题目卡片背景

## 六、分阶段实施计划

### 阶段0：素材与角色准备（2-3天）

**目标**：生成完整的魔法岛美术素材和嘟嘟角色

- 用AI文生图生成嘟嘟的正面/侧面/开心/难过/惊讶等多套表情
- 生成数字草原的地形、装饰物（花、蘑菇、水晶）
- 生成蘑菇屋内外场景
- 生成UI元素（水晶图标、对话框、按钮样式）
- 用TTS调校嘟嘟的专属声音（选择音色、调整语调）

**交付物**：素材资源文件夹 + 嘟嘟角色设定文档

### 阶段1：对话内核MVP（3-5天）

**目标**：嘟嘟能说话、有记忆、能进行简单的迎接和反馈对话

- 搭建FastAPI后端 + 数据库核心表
- 实现对话模板系统（迎接/答对/答错/告别等 ~10个模板）
- 实现L1基础记忆（名字、年龄、进度）
- 前端：嘟嘟角色展示 + 对话气泡 + 简单动画
- 集成TTS：嘟嘟说的话有声音

**可测试**：打开页面 → 嘟嘟迎接，问名字 → 记住名字 → 下次打开还记得

### 阶段2：数字草原 + 基础题目（5-7天）

**目标**：完成区域1的全部5个关卡，可进行完整的15分钟学习会话

- 实现探索模式（Canvas 2D地图 + 手柄操控移动）
- 实现挑战模式（题目展示 + 答案输入 + 嘟嘟反馈）
- 实现数字草原5个关卡的题目内容
- 实现积分/水晶系统
- 实现每日会话流程（迎接→探索→挑战→告别）
- 大屏投屏适配（1920×1080，大字体，大元素）

**可测试**：父女一起完成一次完整的15分钟学习会话

### 阶段3：亲子轮流协作（3-5天）

**目标**：实现轮流机制、蘑菇屋装饰、亲密度系统

- 实现家长/孩子角色切换
- 实现Boss合作题（轮流答题联动）
- 实现蘑菇屋装饰系统（用水晶兑换装饰品）
- 实现嘟嘟亲密度等级（每天来学习→亲密度提升→解锁新互动）
- 实现简单的家长学习报告

**可测试**：亲子轮流完成一次包含Boss战的完整会话

### 阶段4：AI深度记忆（5-7天）

**目标**：L2学习记忆就位，嘟嘟能真正"记住"孩子的学习状态

- 实现学习记忆系统（薄弱点追踪、速度变化、常犯错误类型）
- 实现记忆驱动的个性化对话（"上次7+5你做了三次才学会，这次试试8+5？"）
- 实现错题自动归集和同类题生成
- 实现"嘟嘟也一起学"机制（答错时嘟嘟也会困惑，让孩子教它）

**可测试**：连续使用一周后，嘟嘟能根据历史表现给出个性化互动

### 阶段5：加法森林 + 减法山洞（7-10天）

**目标**：完成区域2和区域3的内容和题目

- 实现凑十法动画演示
- 实现破十法动画演示
- 实现加法森林全部关卡
- 实现减法山洞全部关卡
- 实现岛屿地图的区域解锁联动

**可测试**：孩子完成从数字草原到减法山洞的完整进阶

### 阶段6：打磨 + 内测（持续）

**目标**：基于孩子真实使用反馈持续迭代

- 收集孩子使用数据（哪些题卡住、哪个环节最喜欢）
- 优化对话模板（哪些话孩子有反应、哪些无感）
- 调整难度曲线
- 修复bug

## 九、风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 孩子不喜欢嘟嘟 | 阶段0先做角色原型图给孩子看，不喜欢就换；对话模板灵活可调 |
| AI对话成本超预期 | 模板+参数化方案本身就省成本；预生成冷启动对话库覆盖80%场景 |
| 数学内容不够准确 | AI出题后加校验层（计算验证）；初期只用简单题型降低出错概率 |

## 十、验证方法

### 阶段0完成验证
- 把嘟嘟的表情图给孩子看，观察她的第一反应（兴奋？无感？）
- 她会给嘟嘟起什么名字？

### 阶段2完成验证（最关键）
- 女儿第一次完整使用后是否主动说"明天我还想玩"？
- 她是否能用语言描述嘟嘟是谁？（"嘟嘟是我的数学小兔子"）
- 第二天是否自己想起要"找嘟嘟"？

### 持续验证
- 连续使用天数（留存）
- 每关完成后的表情反应（愉悦/无聊/沮丧）
- 家长观察：她是否在非学习时间提到嘟嘟？
- 数学能力变化（每两周对比口算速度和准确率）
